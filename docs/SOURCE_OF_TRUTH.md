# Source of Truth and Context Hygiene

## Controlling hierarchy

When sources disagree, use this order:

1. Founder locks and newest explicit decisions
2. Current controlling Launch Command Centre
3. Current approved Brand Kit / Supplier operating documents
4. Written supplier/customer/payment/store evidence
5. Live connected-system state
6. Current research and working notes
7. Historical drafts and superseded trackers
8. Memory

## Rules

### Newest explicit instruction wins
A newer direct decision replaces an older working assumption unless the older item is explicitly locked.

### Evidence beats inference
A sent-email reference beats "we probably sent it."
A supplier reply beats a catalogue guess.
A live store setting beats an old setup note.

### Status must be earned
Allowed operational status examples:
- not started
- in progress
- waiting on external
- needs founder action
- blocked
- ready
- completed
- deferred

Never convert "drafted" into "sent."
Never convert "planned" into "configured."
Never convert "sample requested" into "sample approved."

### Separate fact types

Every important entry should be recognisable as one of:
- founder decision
- source fact
- derived calculation
- working assumption
- recommendation

Working assumptions must not masquerade as facts.

### Controlling files

Private controlling files currently include:
- House_of_Monakshi_Launch_Command_Centre_v13.xlsx
- House_of_Monakshi_Supplier_Brand_Kit_v1
- Monakshi Supplier Comparison Matrix

When a later explicitly controlling version is created, it supersedes the earlier version for current state but does not erase history.

### Connected systems

For live status, prefer the system that owns the state:
- Gmail for sent/draft/reply truth
- Wix for store/checkout/order truth
- payment provider for payment truth
- Instagram/Metricool for publishing truth
- Google Drive for private document truth
- GitHub for Monakshi OS code/system truth

### Historical material

Historical data may contain useful ideas and evidence, but it cannot silently override:
- current supplier lane
- current payment gateway
- current brand identity
- current launch product criteria
- current website state
- current legal/compliance position

## Contradiction handling

When two current-looking sources conflict:
1. surface the conflict
2. identify both sources
3. prefer the higher-authority/newer evidence
4. mark the lower source stale or superseded
5. record the resolution

Never average contradictions into a vague middle.

## Privacy

The source registry may store metadata about a confidential file, but the public repository must not store its confidential contents.

Safe public metadata:
- title
- document type
- version
- authority level
- last verified date
- broad purpose

Private:
- negotiated commercial terms
- customer/order/payment data
- private contact details
- confidential attachments
